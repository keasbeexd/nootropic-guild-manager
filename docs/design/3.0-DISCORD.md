# Nootropic Guild Manager 3.0: Discord and the web

Status: **draft for discussion. Nothing here is built yet.** Decisions marked **[open]** need an answer before any work starts.

## 1. Goals

1. **Everything from in game reaches Discord, and Discord reaches the game**: events, sign-ups, roles, ranks, announcements.
2. **Works for any guild**, set up in minutes by a non-technical officer.
3. **Discord is optional.** A guild that never connects anything keeps today's addon, unchanged and complete.
4. **Replaces the GuildsForever bot** for our guild: verified links between Discord accounts and characters, rank and class roles.
5. **Data from members who are rarely online still spreads** (the "async" question from 2.9).

## 2. The three places data lives

```
 ┌──────────────── IN GAME ────────────────┐        ┌────── BLIZZARD SERVERS ──────┐
 │  The addon ⇄ guildmates' addons         │        │  WoW: Forever web API         │
 │  (sync over guild chat, as today:       │        │  (read only): guild roster,   │
 │   profiles, recipes, play hours,        │        │  characters, statistics,      │
 │   Hall of Fame, events...)              │        │  "Sign in with Battle.net"    │
 └──────▲───────────────────────┬──────────┘        └──────────────┬────────────────┘
        │ BRIDGE                │ BRIDGE                           │ read by
        │ (Discord → game)      │ (game → Discord)                 ▼
        │                       │                        ┌──────────────────────────┐
        └───────────────────────┴───────────────────────►│  NGM SERVICE + BOT        │
                                                         └────────────┬─────────────┘
                                                                      ▼
                                                         ┌──────────────────────────┐
                                                         │  DISCORD: roles, events,  │
                                                         │  sign-ups, posts           │
                                                         └───────────────────────────┘
```

- **In game.** Addons can't use the internet. The game reads files on your own disk at login and `/reload`, and writes the addon's saved data at logout and `/reload`. Between players, data moves only through the addon's own sync over guild chat. That sync is unchanged in 3.0 and still carries everything addon-only.
- **Blizzard servers.** A read-only web API. It is **not officially documented for Forever yet**, but developers report it working (sources in §9): guild rosters, character profiles, statistics, and Battle.net sign-in. It has **no calendar or events**.
- **Discord.** Events live here, as Discord's own scheduled events. A bot reads and writes them, gives roles and posts messages.
- **Bridges** are needed only to cross between the game and the service. Everything the service can learn from Blizzard's API needs no bridge.

## 3. What each part can do

| Feature | Source of truth | Needs a bridge? |
|---|---|---|
| Linking a Discord account to characters (verified) | Battle.net sign-in through the service | No |
| Discord roles from rank, class, main, level | Blizzard guild roster API | No |
| New member / left guild / promotion posts | Blizzard guild roster API (polled) | No |
| Hall of Fame verified against Blizzard's own statistics | Blizzard character statistics API | No (in game it stays addon sync) |
| Events shown in game, with countdowns and reminders | Discord scheduled events | **Yes**, Discord → game |
| Signing up for an event from in game | The addon | **Yes**, game → Discord |
| Signing up from Discord | Discord | **Yes**, Discord → game (to show in game) |
| Events created by officers in game | The addon | **Yes**, game → Discord |
| Profiles, recipes, play hours, Discord names | The addon | Only to reach offline members faster (the async store) |
| Champions and announcements posted to Discord | The addon (or the service, from the API) | Game → Discord, or none if the service computes them |

## 4. Tiers (each guild picks one)

| Tier | What the guild does | What it gets |
|---|---|---|
| **0. No Discord** | Nothing | Today's addon, complete |
| **1. Webhooks** | Pastes a Discord webhook URL into the addon's options | Game → Discord posts (champions, events created in game, announcements), through a bridge. No bot, no roles, nothing back into the game. |
| **2. Self-hosted** | Runs the open-source NGM service and bot themselves (one command or a Docker image) with their own Discord bot token and Blizzard API keys | Everything, on their own machine |
| **3. Hosted** | Invites the NGM bot, runs `/ngm setup` in Discord, signs in with Battle.net | Everything; we run it |

**[open] Paying for hosting.** Blizzard's UI Add-On Development Policy, rule 1: "All add-ons must be distributed free of charge", no "premium" versions with "for-pay features", and no charging for "services related to the add-on" (§9). A paid hosted tier that powers features of the addon very likely breaks that, and the risk is the addon being removed or blocked. Policy-safe options:
- **(a) Free hosting, funded by donations.** A Ko-fi or GitHub Sponsors link on the website, CurseForge and GitHub only, never in game (rule 5). Optionally a soft cap: guilds above a size, or self-hosters, run their own.
- **(b) Free, with self-hosting** for anyone who'd rather not depend on us.
- **(c) Ask Blizzard** before charging for anything.

Recommendation: (a) with (b). Costs for a small service are low: one small server, plus Blizzard API calls within its free quota.

## 5. Bridges (each guild picks one or more)

| Bridge | How it works | Install? | Speed |
|---|---|---|---|
| **Copy-paste strings** (always available) | `/ngm export` shows a text block; paste it into `/ngm import` in Discord. The bot answers with a block for `/ngm import` in game. Like WeakAuras strings: compressed, checked for tampering. | Nothing | Manual |
| **Web companion** | An officer opens the NGM web page in Chrome or Edge and picks their WoW folder once. While the tab is open it reads the saved data after each logout or `/reload` and writes a small data addon the game loads at the next login or `/reload`. | Nothing (a browser tab) | Each logout or `/reload` |
| **Desktop companion** (optional, later) | The same, as a background app (the WeakAuras Companion model) | An app | Each logout or `/reload` |

Notes:
- Writing goes into a separate **data addon** (for example `NootropicGuildManager_Data`), never the saved-data file. The game overwrites saved data at logout, but never touches addon files.
- **One bridge per guild is enough.** The addon's sync spreads what one officer's bridge brings in to everyone in game. More bridges just mean fresher data.
- The web companion relies on a browser feature (the File System Access API) that only Chromium browsers have, and it asks for folder permission each session.

## 6. Identity: linking Discord and characters

1. In Discord, `/ngm link` gives a "Sign in with Battle.net" button.
2. The service reads the member's Forever characters with their permission, then links the Discord account to them and their guild.
3. Roles follow from the guild roster API: rank, class of the main, level bands, and "Raider" if the guild wants it.
4. Unlinking, or leaving the guild, removes the roles (configurable).

This replaces the GuildsForever bot's linking and role job. No in-game step or bridge is needed.

## 7. Events

- **Discord is the home of events** (native scheduled events). The bot can also create them from the in-game Events page (officers), through a bridge.
- **In game:** an **Events** page with upcoming events, countdowns, a login reminder ("Onyxia tonight at 8 pm"), sign-ups with character, class and role, and readiness warnings (attunement, level).
- **Sign-ups both ways:** from Discord (a button on the event post) or in game (through a bridge).
- **Not possible:** writing into the game's own calendar. Forever blocks addons from doing that.

## 8. The async data store (from the 2.9 discussion)

With tier 2 or 3, each bridge uploads what its copy knows and downloads what others uploaded. A member who never overlaps with an officer still gets their profile, recipes and Hall of Fame numbers to everyone, through any bridge. The service records which bridge uploaded what, and checks the Hall of Fame against Blizzard's statistics, so this doesn't open a way to forge data.

## 9. Sources

- WoW: Forever API, what works so far (community, not Blizzard staff): https://us.forums.blizzard.com/en/blizzard/t/wow-forever-api-what-works-so-far-plus-a-ts-client/60334
  - Namespaces `profile-forever-{region}`, `static-forever-{region}`, `dynamic-forever-{region}`; guild roster at `/data/wow/guild/{guild-slug}/roster`; character profile and sub-endpoints (statistics, achievements); account profile through Battle.net sign-in (can lag 20–40 minutes). No calendar.
  - Projects already using it: Raid-Ledger's guild roster sync (https://github.com/sjdodge123/Raid-Ledger/pull/1991), Everloot (https://github.com/Everloot/everloot/pull/867), and a TypeScript client (`@pinta365/blizzard-api`).
- Blizzard UI Add-On Development Policy: https://us.forums.blizzard.com/en/wow/t/ui-add-on-development-policy/24534 (rule 1 free of charge, rule 4 no advertising, rule 5 donations only outside the game)
- GuildsForever: https://guildsforever.com/ (guild finder, events, raid planner, bot notifications; free)

## 10. Phases (proposal)

1. **3.0: foundation.** In-game Events page (events created by officers in game, synced by the addon), the export/import string format, webhooks (tier 1), the data addon.
2. **3.1: service and bot.** Battle.net linking, roles from the roster, Discord events → game, sign-ups both ways, hosted and self-hosted (tiers 2 and 3), the web companion.
3. **3.2: community and async.** The async data store, posts from roster changes, Hall of Fame verified against the API, recruitment posts.
