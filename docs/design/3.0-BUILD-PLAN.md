# NGM 3.0 build plan: NGM Hub and NGM Peon (no connector)

Status: **plan for review.** Milestone 1 (the skeleton) is built: private repo `keasbeexd/ngm-hub`, PR #1. Updated after addon 2.12 (2026-11-11); see the note at the top of 3.0-DISCORD.md. Companion to [3.0-DISCORD.md](3.0-DISCORD.md), which says *what* and *why*. This says *how* and *in what order* for phase 3.0: everything that works with **no connector**. Items marked **[decide]** need your call; **[verify]** needs a fact checked.

## 1. Scope of 3.0

**In:**
1. Inviting **NGM Peon** to a Discord server, and `/ngm setup` by the Guild Master with Battle.net sign-in.
2. Member linking (`/ngm link`, Battle.net).
3. **Rank roles** mirroring the guild's in-game ranks; optional class, main/alt and level-band roles.
4. **Roster events** from Blizzard's API: joins, leaves, promotions and demotions, level-ups and level 60, each posted in a channel the guild picks.
5. **Activity:** Social Butterfly blocks from in-game guild chat (Blizzard's link), Discord text and Discord voice; "last seen" anywhere.
6. **Auto-ranks** (off by default): rules; Discord roles change; officers are told in Discord to promote in game.
7. **Settings** with `/ngm settings`; **privacy** with `/ngm privacy`.
9. **Managed posts** (`/ngm post`): pinned info posts created and edited from Discord, optionally with live guild data. Replaces today's Peon `--post` and `--update`, so the old script can retire. Plus `/ngm inventory`, a private read-only report for server admins.
8. **Addon:** the setup code (`/ngm discord` in game): rank names, and which ranks the game marks Officer and Invite Member. That's the only addon change in 3.0.

**Out (later phases):** server templates (`/ngm server setup`: build a recommended guild server with roles, channels, permissions, onboarding and posts, previewed first, never deleting unless asked; our layout as the first template), the connector, anything shown *in game* from Discord, `/profile` and `/craft` (they need addon data), events and sign-ups, public guild pages, the Hall of Fame from Blizzard's statistics, the desktop connector.

## 2. Components

```
                 ┌──────────────────────── NGM HUB (our servers) ────────────────────────┐
 Discord ◄──────►│  NGM Peon (bot process)     Web (sign-in pages, later public pages)   │
                 │        │                           │                                   │
                 │        └──────► Core (rules, activity, roster diff) ◄──── Jobs ───────┼──► Blizzard web API
                 │                         │                    (roster poll, daily tidy) │    (Forever namespaces)
                 │                      Database                                          │
                 └────────────────────────────────────────────────────────────────────────┘
```

- **NGM Peon:** one Discord bot process for every guild. It handles slash commands, listens to messages (who and when only) and voice joins and leaves, and gives roles and posts.
- **Web:** only what Battle.net sign-in needs in 3.0 (start, callback, "you can close this tab"). Public pages come later on the same server.
- **Core:** the shared logic, used by bot, web and jobs.
- **Jobs:** the roster poll per guild, and a daily tidy (expiring old data, recomputing).
- **Database:** one, with every guild's data kept separate by guild.

## 4. Accounts and keys we need

- **Discord application "NGM Peon":** our existing **Nootropic Peon** application, renamed (the application and the bot user) ✅ decided. It's already in our server. Public Bot stays off until launch. Its token is shared with the old Peon script until managed posts replace it (milestone 7b); then reset it so only the Hub holds it, and trim its role in our server to the permissions below.
  - Bot permissions: Manage Roles, View Channels, Send Messages, Embed Links, Read Message History.
  - **Gateway intents:** Guilds, Guild Messages (message *events* only, not content), Guild Voice States, and **Guild Members**. Guild Members is privileged: a toggle in the developer portal, and Discord's verification once the bot is in 75–100 servers.
  - **No Message Content intent.** We never need it.
- **Blizzard API client** (develop.battle.net): client ID and secret, a redirect address on the Hub, scope `wow.profile`.
- **Server secrets** stay on the server only, never in the repository.

## 5. Data model (simplified)

| Table | Holds |
|---|---|
| `guilds` | Discord server ↔ in-game guild (slug, region), rank names, settings, privacy switch |
| `characters` | Characters from the roster: name, class, level, rank number, first seen, last seen in game |
| `people` | One per person: their main and alts (from the roster's main/alt data, or linking) |
| `discord_accounts` | Discord user IDs: linked real accounts, and Blizzard's per-character stand-in IDs matched by character name |
| `links` | Person ↔ Discord account ↔ Battle.net account (verified by sign-in) |
| `activity_blocks` | (person, 15-minute block, sources: game / Discord text / voice), plus a daily count for the cap |
| `roster_events` | Joins, leaves, rank changes, level-ups (for posts and auto-ranks) |
| `rules` | Auto-rank rules per guild |
| `opt_outs` | Members who opted out of counting, linking or naming |

Not stored: message text, Battle.net tokens (used once at sign-in, then dropped), anything about non-members.

## 6. Flows

### 6.1 Guild setup (Guild Master, once)
1. In game, the Guild Master types **`/ngm discord`**. The addon shows a short **setup code** with the guild's rank names (Blizzard's API has rank numbers only, never names) and which ranks the game marks **Officer** and **Invite Member** (the addon reads these since 2.12; the Guild Master's copy can always read them).
2. In Discord, someone with Manage Server invites NGM Peon. The Guild Master runs **`/ngm setup`** and pastes the code.
3. Peon replies with a private **Sign in with Battle.net** button. The Hub sees their Forever characters; one that is rank 0 (Guild Master) in a guild proves who they are, and binds that guild to this Discord server.
4. Peon creates or adopts **rank roles** named after the ranks (plus optional Officer and Recruiter roles from those settings), and asks which channels to post in (with defaults).
5. Optional reminder shown: link guild chat to a channel with Blizzard's own Discord setting. Never an officer channel.

### 6.2 Member linking
1. `/ngm link` → Battle.net sign-in → the Hub finds their characters in that guild.
2. Their Discord account is linked to that person (main and alts). They get their rank role, and optional class and level roles.
3. `/ngm unlink` removes the link and the roles.

### 6.3 Roster sync (job)
- **Polls each guild's roster** every 10–15 minutes **[verify]** (rate limits: 36,000 requests an hour, 100 a second, per API client; plenty for hundreds of guilds).
- **Compares with the last snapshot:** joins, leaves, rank changes, level changes, and posts each in its channel.
- **Updates roles** for linked members (rank changed → role changed).

### 6.4 Activity (bot events)
- **Every message** in the server: if it's from Blizzard's app (`application_id 1384671873593512078`) it counts as **in-game chat**. A real account is a linked person; a stand-in ID is matched to a character by its name. Anything else counts as **Discord text**.
- **Voice:** a member is in voice with at least one other human → each 15-minute block counts as **voice**.
- **The rule:** a block counts if the person was active in it and someone else was too. At most 8 a day. Sources merge, never add.
- **Last seen:** the latest of in game (roster or chat), Discord text, voice.
- **Members who opted out** aren't recorded.

### 6.5 Auto-ranks (off by default)
- Rules like "rank 4 → rank 3 after 14 days in the guild and 5 hours Social Butterfly". Days in the guild count from the first roster snapshot that included them; the addon's join dates arrive in 3.1.
- When met: the Discord role changes (if the guild allows it), and Peon tells officers in their chosen channel: "Rat Legend qualifies for Member. Promote in game." The in-game prompt comes in 3.1, and the officer completes it in the game's own guild window (addons can't change ranks).
- Demotions are only ever suggested, never automatic.

### 6.6 Settings and privacy
- **`/ngm settings`** (Guild Master, or officers if allowed): channels, which roles to sync, Social Butterfly sources (voice on by default), auto-rank rules on or off, public page switch (used from 3.2).
- **`/ngm privacy`** (any member): don't count me, don't name me in posts, unlink me and delete my data.

## 7. Addon changes in 3.0
- **`/ngm discord`**: a window with the setup code (rank names, which ranks are Officer and Invite Member, guild name and region, with a checksum so typos are caught), with a copy button. Officers only. Copying uses a box the player selects and copies themselves (Ctrl+C), as the Invite prompt does; addon code doesn't touch the chat box.
- Nothing else. The addon keeps working exactly as today with or without the Hub.
- **Ready for 3.1:** the records in `Core/Records.lua` are what the connector carries, under the same rules, and per-author fingerprints (`S:AuthorSums` in `Core/Sync.lua`) are how it finds what the Hub lacks. 3.0 changes neither.

## 8. Security
- **Battle.net sign-in:** standard OAuth with a one-time state (no cross-site request forgery). Tokens are used once and dropped.
- **Who controls a guild:** only a verified Guild Master (rank 0 through Battle.net) can bind a guild or change who manages its settings. Officers are added by rank.
- **Every guild's data separated** in every query, with tests that one guild can't read another's.
- **Rate limits** on commands and sign-ins. Peon's roles kept to the minimum it needs. Its role must sit above the rank roles it manages, or it can't assign them.
- **Secrets:** environment only; automated backups encrypted.
- **An audit log** of every role change and setting change.

## 9. Operations
- **Hosting:** a single VPS with Docker Compose (bot, web, jobs, PostgreSQL), nightly encrypted database backups to the Storage Share (off the server), and an uptime check.
- **Costs:** about $5–10 a month for the server, about $10–20 a year for a domain, and nothing for Discord or Blizzard.
- **Deploying:** push to the private repo → automated tests → deploy.

## 10. Testing
- **Unit tests:** the activity rule (blocks, cap, merging), roster comparisons, auto-rank rules, setup-code parsing.
- **A private Discord test server,** and a test guild in game (yours) for the end-to-end run.
- **Before inviting other guilds:** run alongside the current bots in our own server for a couple of weeks.

## 12. Nootropic's switch-over
- **NGM Peon takes over:** linking, rank roles, roster posts and activity.
- **Nootropic Peon (the script):** **retires** ✅ decided. Its posts move to managed posts in 3.0; its server-building becomes server templates in 3.2. Until then the server layout simply stays as it is.
- **Nootropic Grunt (MEE6):** unchanged; moderation.
- **Guilds Forever bot:** removed after the two weeks side by side.
